# Getting Support

Project Echo is in beta, so some behaviour and platform support may change.

## Before asking for help

1. Check the README and [Platform Support](docs/PLATFORM_SUPPORT.md).
2. Confirm you are using the latest project version available to you.
3. Reproduce the problem with a minimal example or non-sensitive test document.
4. Collect the Echo version, operating system/version, relevant provider/model, and the exact error message.

## Where to ask

- Use GitHub Issues for reproducible bugs and feature requests.
- Use GitHub Discussions for usage questions, ideas, and general feedback when Discussions are enabled.
- Use private vulnerability reporting for security issues; see [SECURITY.md](SECURITY.md).

## Do not post

Never post API keys, `.env` contents, access tokens, screenshots containing secrets, private documents, personal information, captured meeting audio, or transcripts. Redact paths that reveal private usernames or organisation names.

## What to include in a bug report

- Echo version or commit.
- Operating system and version.
- Steps to reproduce.
- Expected result and actual result.
- Exact error text and relevant redacted logs.
- Whether the issue occurs with another provider or a clean sample project.
